# Project rules

## Source of truth
PLAN.md is the spec. Work through it in order.

## When something isn't in the plan
If you hit a decision, requirement, or missing dependency that PLAN.md
doesn't cover — don't guess or pick a default. Stop, write the question
to NEEDS-INPUT.md with enough context to answer in one line, and leave
the item unchecked.

## Verification
Before checking off any PLAN.md item, run its tests and show the
actual output in your response — not just "tests pass." The completion
checker only sees what's visible in the conversation, so silent test
runs don't count as proof.
